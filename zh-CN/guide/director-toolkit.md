# 导演工具箱

## 三分钟上手

Opus 5.5 本身不输出视频。它写代码画出每一帧（HTML Canvas、SVG、Three.js、Remotion、HyperFrames、Manim）， 在无头浏览器里逐帧渲染，再用 ffmpeg 合成 MP4。所以它擅长动效、科普讲解和发布片；想改哪里，是改一行代码重新渲染， 而不是重新抽卡。

1. 打开 Claude Code（或 Claude App），模型选 Opus 5.5，effort 调到 high 或 max。
2. 装一个渲染器，让它能直接出 MP4：`npx skills add heygen-com/hyperframes` 或 `npx skills add remotion-dev/skills`。本机需要 Node 22+、Chrome 和 ffmpeg。
3. 新建一个空文件夹，从本列表挑一条提示词粘进去，把主题、品牌和素材换成你自己的。
4. 正式渲染前，先让它每个场景出一张静帧；确认后再像导演一样给修改意见（见下方导演词汇表）。

## 六步导演法

改写自 @rexan_wong 的串推。他逆向拆解了一批号称「一句 prompt」的爆款视频。 [↗](https://x.com/rexan_wong/status/2103707054108299437)

### 1. 选参考片

挑一两条你想要的节奏和字体风格的视频，让 Opus 照着做。点名一种风格，比描述一种风格好用得多。没有参考，它会退回默认样子：居中文字、渐变背景、所有东西淡入。

### 2. 装渲染器

装 HyperFrames 或 Remotion，它就能把每个场景写成代码、直接渲染成 MP4。每一帧都是确定的，改一处只动一行，不用推倒重来。

### 3. 用真素材

给它你的真实截图、Logo 和界面组件，别让它自己编按钮和卡片。编出来的界面，是视频看起来廉价的开始。

### 4. 一次给足上下文，要三版分镜

品牌、配色、字体、截图、参考片，再口述一遍你脑子里的片子。要三版分镜，你是在挑方向，而不是去修它的第一个想法。

### 5. 先审静帧，再动起来

每个场景先出一张静帧。改分镜只要几秒，改成片就得重新渲染。

### 6. 像导演一样给意见

第一版通常已经完成了大半。「再好一点」只会换来随机改动，用镜头语言才能精确改到你想要的地方。

## 一条专业提示词的结构

结构来自 @twoclipping 公开的模板，它是本列表收藏最多的一条提示词（1.9 万+ 收藏）。 [↗](https://x.com/twoclipping/status/2103273003555402193)

| 段落 | 写什么 |
|---|---|
| `<inputs>` | 开工前它要向你要的东西，比如品牌名、8–12 张照片或界面状态、一首 120 BPM 左右的免版权音乐。 |
| `<direction>` | 一段话写清画风，再加一份禁用清单（淡入淡出、发光、粒子、停留超过一秒、任何像模板的东西）。禁用清单比风格形容词更管用。 |
| `<structure>` | 节拍网格加场景链，比如「120 BPM，54 拍，每一拍都有事发生」，每个场景从上一个场景里长出来。 |
| `<build>` | 让它能稳定渲染的工程约束，比如单个 HTML 文件、所有数值都由 seek(t) 里的时间算出、闭式弹簧动画、先分析节拍、子帧运动模糊。 |
| `<gotchas>` | 已知的翻车点，比如镜头缩放后文字发糊、文字切换重叠、循环首尾接不上。 |
| `<start>` | 第一步做什么，通常是「先问我要素材，写代码前先给我看计划」。 |

## 导演词汇表

别再说「再好一点」，换成这些词。每一个都对应 Opus 能在代码里做出的具体改动。

| 术语 | 你想要 | 这样说 |
|---|---|---|
| `push in` | 强调某个元素 | 镜头往按钮推近，用 0.8 秒。 |
| `pull out` | 揭示全貌 | 从图表局部开始，拉远到整页。 |
| `hard cut on the beat` | 换场卡在节拍上 | 这里硬切，落在第 17 拍。 |
| `match cut / morph` | 场景之间连贯 | 上一镜的圆直接变成下一镜的 logo。 |
| `one continuous take` | 去掉幻灯片感 | 全程不切镜，每个场景都从上一个场景里长出来。 |
| `hold` | 让人读完字 | 这句话停 1.5 秒再走。 |
| `slow to 0.7x` | 太快太躁 | 所有缩放放慢到 0.7 倍。 |
| `stagger` | 元素一起蹦出来太乱 | 卡片依次进场，间隔 80 毫秒。 |
| `ease-out / spring` | 动作太机械 | 改成弹簧动画，只带一点点回弹，不要弹跳缓动。 |
| `parallax` | 画面太平 | 前景比背景移动得快。 |
| `rack focus / depth of field` | 焦点不清 | 背景虚化，只留产品清晰。 |
| `mask reveal` | 更高级的文字出场 | 文字从一条遮罩线里升起来，而不是淡入。 |
| `kinetic typography` | 让文字本身带节奏 | 旁白逐词出现，和音频波形对齐。 |
| `whip pan` | 有冲劲的转场 | 带运动模糊快速横甩到下一个场景。 |
| `speed ramp` | 让关键瞬间更有力 | 高潮前降到 0.3 倍速，然后猛地恢复。 |
| `screen-studio zoom` | 产品演示跟着操作走 | 光标点到哪里镜头就推到哪里铺满画面，光标跟着一起放大。 |
| `seamless loop` | 能在官网循环播放 | 最后一帧和第一帧完全一致，光标位置和速度也要一致。 |
| `beat grid` | 所有动作和音乐同步 | 先分析歌曲节拍，每一拍安排一个变化。 |

## 一句话默认病体检表

拿到第一版成片后，先对照这张表体检，再提修改意见。 七个症状来自 @DavidKPiano，对应的改法是本列表整理的。 [↗](https://x.com/DavidKPiano/status/2103919227853783445)

| 症状 | 改法 |
|---|---|
| 节奏太快。 | 所有运动放慢到 0.7 倍，关键文字至少停留 1 秒。 |
| 特效太多。 | 在提示词里加禁用清单（发光、粒子、淡入淡出、渐变）。 |
| 没有整体感，东西往各个方向乱动。 | 每个场景只保留一个运动方向，或者要求一镜到底。 |
| 没有视觉焦点。 | 说清每个场景只讲一件事，然后推近它。 |
| 缓动千篇一律。 | 改用轻微回弹的弹簧动画，不同元素用不同节奏。 |
| 没有编排。 | 给它一张节拍网格，每一拍只安排一个变化。 |
| 为动而动。 | 告诉它每个动作要说明什么，比如「柱子变高，表示收入翻倍」。 |
